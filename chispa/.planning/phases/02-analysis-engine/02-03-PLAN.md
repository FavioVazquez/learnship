# Plan 02-03: Integration

<objective>
Replace the stub body in `server/src/routes/analyze.ts` with real Claude agent calls by wiring in the `analyzeIdea` generator from Plan 02-02. The route handler iterates the generator and pipes each yielded SSEMessage to the client via `sendSSE`. This is the integration step that closes the loop: real Claude tool calls flow through the SSE handler to curl, with the rate limiter and error handling from Plan 02-01 still intact.
</objective>

## Context

Plans 02-01 and 02-02 must be complete before this plan runs. After this plan, `server/src/routes/analyze.ts` will have:
- All the same synchronous guard logic (validation, rate limit, flushHeaders) from Plan 02-01
- The stub `setTimeout` and `mockResult` replaced with `for await (const msg of analyzeIdea(idea, country))`
- `res.end()` in `finally` (was already there from Plan 02-01 — confirm it remains)

The `analyzeIdea` generator already handles its own errors internally (yields `{ type: 'error', ... }` on exceptions). However, the route handler should still have a `catch` block for any synchronous exceptions that could escape before the generator even starts.

From RESEARCH.md Pitfall 9: `res.end()` in `finally` is essential — without it, curl hangs after the `result` event. Node.js SSE responses stay open until explicitly closed.

From RESEARCH.md Pitfall 5: the generator uses `for await` with a single `try/catch` internally — the route handler should not also add `.on('error', ...)` to the stream. The generator encapsulates all stream error handling.

The `country` variable is already declared in the route handler from Plan 02-01. It passes through to `analyzeIdea(idea, country)` with no changes.

ESM import rule: `'../agent/analyzer.js'` (`.js` extension required for local imports).

   }
