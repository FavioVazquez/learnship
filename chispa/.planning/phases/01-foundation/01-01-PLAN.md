# Plan 01-01: Server + Client Scaffolding

<objective>
Create both the Express server package and the React client package from scratch. Both must have correct TypeScript configuration, all required dependencies installed, and the shared `AnalysisResult` / `SSEMessage` types defined identically in both. The server must respond to `GET /api/health` and return 501 for `POST /api/analyze`. TypeScript must compile clean in both packages. Integration (the root dev script) is Plan 01-02.
</objective>

## Context

The project uses ESM throughout — `"type": "module"` in both `package.json` files. Server TypeScript uses `"module": "NodeNext"` which requires `.js` extensions on all local imports (see RESEARCH.md Pitfall 1). TypeScript files are `.ts` / `.tsx` but imports reference them as `.js` — this is correct NodeNext behavior.

`tsx` (not `ts-node`) is the TypeScript executor for development. `ts-node` has ESM loader bugs on Node 20+. `nodemon` watches for changes and restarts using `tsx src/index.ts`.

All client dependencies — including `framer-motion`, `recharts`, and `lz-string` — are installed now so Phase 3 and Phase 4 executors can import them without a separate install step.

The health endpoint must NOT expose `model`, `version`, or `nodeVersion` fields (security: fingerprinting). Return only `{ status, timestamp, uptime }`.

<title>Create server/src/index.ts — Express entry point</title>
<files>
- server/src/index.ts

<action>
Create `server/src/index.ts`:

```ts
import 'dotenv/config'
import express from 'express'
import cors from 'cors'
import path from 'path'
import { fileURLToPath } from 'url'
import router from './routes/index.js'

const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)

const app = express()
const PORT = process.env.PORT ?? 3001

app.use(cors())
app.use(express.json())

app.use(express.static(path.join(process.cwd(), '../client/dist')))

app.use(router)

app.use((req, res) => {
  if (req.path.startsWith('/api/')) {
    res.status(404).json({ error: 'Not found' })
  } else {
    res.sendFile(path.join(process.cwd(), '../client/dist/index.html'))
  }
})

app.use((err: Error, _req: express.Request, res: express.Response, _next: express.NextFunction) => {
  console.error(err.stack)
  res.status(500).json({ error: 'Internal server error' })
})

app.listen(PORT, () => {
  console.log(`🌶️  Chispa server running on http://localhost:${PORT}`)
})
```

Note: `import 'dotenv/config'` MUST be the first import. The static serving path uses `process.cwd()` which resolves to `server/` when started via `cd server && npm start`. The `__dirname` reconstruction from `import.meta.url` is available for future use if path resolution needs to be file-relative.
