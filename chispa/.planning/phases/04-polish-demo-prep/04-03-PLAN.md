# Plan 03: Production Build — SPA Served on Port 3001

## Objective

Fix `server/src/index.ts` so that `npm run build && npm start` produces a working production server. There are two bugs to fix simultaneously: (1) the `express.static` path uses `__dirname`-relative resolution that breaks when TypeScript is compiled (compiled output lands in `server/dist/src/`, adding an extra directory level that makes the relative path resolve to the wrong location), and (2) the global catch-all returns a JSON 404 for all unmatched routes instead of serving `index.html` for SPA navigation. Fix both using `process.cwd()`-based absolute paths, and guard the catch-all so `/api/*` routes still get JSON 404s.

## Context

`server/src/index.ts` uses `path.join(__dirname, '../../client/dist')` on line 17 for `express.static`. The `__dirname` ESM shim is constructed from `fileURLToPath(import.meta.url)`, which resolves to the actual file location at runtime. When `tsx` runs source directly, `__dirname` = `chispa/server/src/` and `../../client/dist` correctly points to `chispa/client/dist`. But after `npm run build`, the compiled file is at `chispa/server/dist/src/index.js`, making `__dirname` = `chispa/server/dist/src/` and the same relative path resolves to `chispa/server/client/dist` — a path that does not exist.

The fix: replace ALL `__dirname`-relative paths with `process.cwd()`-based paths. The `npm start` script runs `cd server && npm start`, so `process.cwd()` is always `chispa/server/` at runtime — both in dev (`tsx`) and production (`node dist/src/index.js`).

The `server/tsconfig.json` has `"outDir": "dist"` and `"rootDir": "src"` — confirming that `src/index.ts` compiles to `dist/src/index.js`.

The root `package.json` `build` script (`cd client && npm run build && cd ../server && npm run build`) and `start` script (`cd server && npm start`) are already correct — no changes needed there.

**CONTEXT.md deviation note:** CONTEXT.md suggested `path.join(__dirname, '../../client/dist/index.html')` for the SPA catch-all. This plan intentionally uses `process.cwd()` instead. Reason: after compilation `__dirname` resolves to `server/dist/src/` (not `server/src/`), making the `../..` relative path point to the wrong location. `process.cwd()` is stable regardless of compilation depth — always `chispa/server/` when started via `npm start`. The CONTEXT.md suggestion is correct for dev mode but broken for production.

<action>
Read `server/src/index.ts` first. Make two targeted changes:

**Change 1 — Fix the express.static path (line 17):**

Find:
```typescript
app.use(express.static(path.join(__dirname, '../../client/dist')))
```

Replace with:
```typescript
app.use(express.static(path.join(process.cwd(), '../client/dist')))
```

**Change 2 — Replace the JSON 404 catch-all with a conditional SPA catch-all:**

Find:
```typescript
app.use((_req, res) => {
  res.status(404).json({ error: 'Not found' })
})
```

Replace with:
```typescript
app.use((req, res) => {
  if (req.path.startsWith('/api/')) {
    res.status(404).json({ error: 'Not found' })
  } else {
    res.sendFile(path.join(process.cwd(), '../client/dist/index.html'))
  }
})
```

No other changes. The `path` import, `__dirname` shim, `PORT`, `app`, middleware, `router`, and error handler all stay exactly as they are. The `__dirname` variable itself can remain (it is used by nothing else after this change, but removing unused variables is out of scope).

Important: `res.sendFile` requires an absolute path. `path.join(process.cwd(), '../client/dist/index.html')` produces an absolute path — this is correct.
</action>
